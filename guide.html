AI Welcome Guide

How I use Claude: what to try first, my rules of thumb, and what's in the kit. It's all on one page so you can come back to it. Words you don't know are explained at the bottom.

Want to install the kit or build the Snake demo? That's the step-by-step tutorial.

Your first day

Pick one and paste it into Claude, in chat or in Claude Code. None of them need the kit. Swap in your own details.

I work as [your job]. Ask me a few questions about my week, then name three things you could take off my plate.
Here's something I redo by hand every week: [attach it or describe it]. Show me how you'd do it, and what you'd need from me.
Make a one-page explainer of [something you've been meaning to understand], for someone new to it. Then quiz me on it.
Here's an email I've been putting off: [paste it]. Draft a reply, then ask me what you got wrong.

Work data? Check your employer's rules on AI tools before you paste it in.

Rules of thumb for everyone

These work anywhere, in a plain Claude chat too. kit marks the part that needs the kit installed.

  1. Don't know what you don't know? Ask Claude.

    Keep asking until you get to the bottom of it. That's how you learn to use this. You no longer have to be a programmer to program.

  2. Think like an automator.

    If you're ever doing data entry, ask "can I have Claude do this?" For anything you're doing, ask yourself: can Claude do this, or can we make a skill for it?

  3. Use artifacts to understand what's going on.

    Ask for a page instead of reading a wall of text. "Publish an artifact comparing X and Y" gets you a page you can skim, keep and share.

  4. Play with multimedia.

    Claude isn't just text. It reads PDFs and images, and can transcribe what's in them. It works with your files, and draws things: diagrams, SVGs, charts, whole pages. If it can't do something natively, like generating an image or transcribing audio, it can find or write the right tool for it. So feel free to play.

  5. Make Claude write in your voice.

    I train my agent on my blog. You can do the same with a few things you've written:

    Here are a few things I wrote: [paste them, or give links]. Write a short voice guide from them: how I sound, what I never say, and two examples. In Claude Code, save it as ~/.claude/voice.md and add a line to ~/.claude/CLAUDE.md telling you to use it for anything written as me. In a chat, give it to me to save in my settings.

  6. Context is everything.

    Every new problem gets a fresh workspace with only the context it needs. In Claude Code, that's one folder per project, with its own CLAUDE.md. Don't work out of one giant folder. In a chat, it's a new chat.

    Be as verbose as you like with that context, just don't confuse it - if you're studying bananas, don't mention oranges.

  7. Treat Claude like a junior dev.

    Give it the exact plan, so it can't mess up. The more leniency you give it, the more it takes.

  8. Claude is a reflection of you and what you know.

    It will be sycophantic, so tell it what to do. You're still the driver.

  9. Have agents argue.

    Have them test things against each other: one builds, another attacks it. In a chat, ask a fresh chat to tear apart the first one's answer. /arena kit is the extreme version - a whole bracket of them.

  10. Trust and verify.

    Make Claude prove the output is correct, not just claim it. Ask it how it knows, and check the parts that matter.

    For code, use test-driven development (/tdd kit) and have Claude run your tests. Audit with /ponytail-audit kit. Matt Pocock's closest is /improve-codebase-architecture.

  11. Get excited about working out how to use Claude best.

    Treat it as a thought experiment. Being able to take on any problem is fun.

Rules of thumb for Claude Code

Claude Code is Claude working on your own computer. These only apply there.

  1. Almost always run in auto mode.

    The faster you trust Claude, the faster you get your work done. Press Shift+Tab to cycle permission modes until it says auto, or start with claude --permission-mode auto.

    Auto mode acts without asking each time. Keep it away from real work data or anything you can't undo, until you know how it behaves.

  2. Use Opus 5.5.

    Low or medium effort for actual code implementation. High or xhigh for planning, wayfinding and grilling. /model and /effort change it mid-session.

  3. Effort doesn't mean good or bad output.

    It only means how much Claude thinks and checks its own work. If you planned and ticketed well, code needs low or medium. When you're planning and don't quite know yet, higher effort is OK.

  4. Anything you do more than once, make it a skill. kit

    Have Claude write it, using Matt Pocock's writing-for-agents skill.

  5. Keep your global ~/.claude/CLAUDE.md short.

    It's context for every session you run.

  6. Don't let Claude read sensitive info directly.

    Have it write a script that reads the secret and puts it where it needs to go, so Claude never sees it.

  7. The ticket runbook does most of this for you. kit

    Every ticket works test-first with /tdd, runs the full test suite and gets a ponytail review. Then a separate agent reviews it for bugs, spec and live data. Live data is n/a locally. The one thing it doesn't do is an audit. Run /ponytail-audit yourself every so often.

  8. Watch your context. kit

    The statusline's ctx is how much of the window this session is using. Keep it under about 30%. Past that, /clear or /compact to stay out of the dumb zone.

  9. Budget with the statusline. kit

    5h, 7d and pace tell you how much effort and how many parallel sessions you can throw at a problem. Don't be afraid to work in parallel - just make sure agents working in the same codebase know about each other.

  10. Leave system-tui open. kit

    It doubles as caffeine. It keeps your Mac awake while it runs, so you can walk away and leave your agents working. No Rust, so no system-tui? Run caffeinate -d in a spare terminal tab instead. On Windows, set sleep to Never while agents work.

  11. Name your sessions.

    /rename <name>, or start with claude -n <name>, so you can tell which one is doing what. I name them after their folder or their problem.

  12. The starting flow for a small problem. kit

    1. A new workspace.
    2. /setup-matt-pocock-skills
    3. /grill-with-docs with your plan.
    4. /to-spec
    5. /to-tickets
    6. One subagent per ticket.

    Type the skills - Claude can't start them. The main chat never implements: subagents build every ticket, at medium effort (low for a tiny fix). Bigger? /wayfinder first.

  13. GitHub is your friend.

    Use it to store your work. Claude knows how to organize itself there.

  14. Code is cheap.

    Don't be afraid to refactor or rebuild something if it's not working. It's often faster to rebuild a system or a script than to fix an old one.

  15. Dictate with Wispr Flow.

    Download Wispr Flow and talk to Claude instead of typing. It makes your life so much easier.

Reading the statusline

Opus·medium │ ctx 24% 48k │ 5h 18% ⟳1h30m │ 7d 30% ⟳4d │ pace +13%
  • Opus·medium is the model and effort.
  • ctx is how full this session's context window is. Keep it under about 30%. It only turns yellow at 60%, so don't wait for the color.
  • 5h is how much of your 5-hour usage window you've used, and when it resets (⟳). 7d is the same, for the weekly window.
  • pace compares your 7-day usage with an even burn. + means you're under it, with room to spend. - means you're over it, so slow down.

system-tui

A dashboard for your Mac and your Claude sessions: CPU, memory, disk use by project, network per process, your open sessions and your plan usage. Run system-tui in a spare terminal tab. q quits.

  • Leave it open. It keeps your Mac awake while it runs, so you can walk away and leave your agents working.
  • The disk panel scans your code folder. The first scan takes a couple of minutes.
  • Plan usage fills once a Claude Code session is open - the statusline feeds it.
  • Other folder? bash install.sh --code-dir <folder>
  • Not found? Open a new terminal, so it picks up ~/.cargo/bin.

Arena: make them fight

Hate an answer? /arena hands the exact same task to a crowd of sub-agents, each with a different strategy. They pair off, attack each other's solution, defend and revise, and a judge scores every match. Losers are out, until one solution is left. By Jake Schincariol, MIT.

/arena --quick <task>

--quick starts 16 agents, about 91 sub-agent calls. The default 100 agents is about 595. python3 ~/.claude/skills/arena/bracket.py plan --agents 16 prints the real numbers. Run it in accept-edits or auto mode (Shift+Tab), or you'll approve every file it writes.

It's wasteful. It's also very fun. Arena burns usage fast. Check 5h before and after your first --quick to see what it costs on your plan, and save the full 100 for the answer that matters.

To watch it live, pair it with a living doc and open the link:

Run /arena --quick on <task> and keep a living doc of the bracket - one ticket per match, synced after every round.

Is this safe, and how do I undo it?

You're running other people's code, so here's whose it is and what it does.

PieceWhoseRuns by itself?
kit-living-doc, kit-ticket-runbookMine, in this repoNo, only when used
Statusline, system-tuiMine, on my other GitHub account, constdecimals9The statusline runs every 10 seconds in Claude Code. system-tui only runs while you have it open
arenaJake SchincariolNo, only when you type it
mattpocock-skillsMatt Pocock, from Anthropic's plugin marketplaceClaude can pick its skills up when they fit
frontend-designAnthropic, from the same marketplaceClaude can pick it up when it fits
ponytailDietrich GebertYes. Its hooks run in every project, on every session and prompt, and add instructions. It logs a cost line per turn to ~/.config/ponytail/band/, on your Mac
  • What changes: ~/.claude, plus one PATH line in your shell file if system-tui needs it.
  • Backups: anything replaced goes to ~/.claude/backups/ first. It keeps skills and a statusline you already have, unless you ask.
  • Not pinned: everything tracks its latest version, so a rerun gets whatever its author has published since. Read it first if that matters to you.
  • Leave things out: bash install.sh --skip arena,ponytail
  • Undo it: bash ~/src/ai-welcome-kit/uninstall.sh removes what the kit added and keeps what you had.

Words you'll see

Claude Code
Claude working on your own computer, from the terminal or the desktop app's Code tab. It can read and change files and run commands.
Claude chat
Claude on claude.ai or in the desktop app's chat. It can't touch your computer.
Skill
A saved set of instructions Claude follows for one kind of job.
Plugin
A bundle of skills and settings you install in one go.
CLAUDE.md
A notes file Claude reads at the start of every session. The one in ~/.claude applies everywhere, and one in a project folder applies there.
Context
Everything Claude is holding in mind in this session. It fills up, and answers get worse as it does.
Effort
How long Claude thinks before it answers.
Artifact
A page Claude publishes that you can open in a browser, keep and share.
Subagent
A second Claude that the first one starts to do one job.
Ticket
One small piece of work, written down in a file.
Living doc
A progress page for a set of tickets.
Statusline
The line at the bottom of Claude Code. The kit's shows your usage.
